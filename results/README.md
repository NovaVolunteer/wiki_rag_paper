# Five-condition results

Raw rows: `results/<condition>.jsonl` and `.csv`. There is one row per question, holding the answer, the judge output, the outcome, input tokens, units seen and gold coverage.
Summary: `results/RESULTS.md` and `results/summary.json`. Regenerate both with `python analyze_conditions.py`.
Full run log: `results/run_full.log`. `results/archive_59q/` holds the abandoned partial C0 run on the old 59-question set.

## Question set: `course_questions_raw.json` (100 questions)

The questions were generated by `generate_questions.py` with gpt-5.5 from the **raw course files only**; the generator never saw the wiki.

- **45 topic-page:** 6–7 per topic.
- **45 cross-page:** 2 for each of the 21 topic pairs, plus 3 that span three topics.
- **10 unanswerable controls:** each was checked against the full raw corpus.

Every question has a reference answer and its gold raw files. A gold file's topic folder gives the gold wiki page. **The instructor is reviewing the questions and may edit them by hand.** After edits, run `python eval_conditions.py --condition all --resume`. Rows whose question text or reference answer no longer matches the file are rerun automatically. The unanswerable controls on the gap statistic, `ccp_alpha` and `min_impurity_decrease` concern topics the material *mentions* without explaining.

## How to run

```
python raw_corpus.py                                   # extract raw text -> raw_corpus.json
python generate_questions.py                           # -> course_questions_raw.json
python eval_conditions.py --condition A-ret --build-index --limit 0   # Pinecone ns raw-v2 (203 chunks)
python eval_conditions.py --condition all              # primary: k=10 / 15,000-token B-nav budget; add --resume to rerun missing/errored rows
python eval_conditions.py --condition A-ret --top-k 5 --results-dir results/budget7500   # sensitivity: k=5 / 7,500
python eval_conditions.py --condition B-nav --top-k 5 --results-dir results/budget7500
python analyze_conditions.py
python analyze_conditions.py --results-dir results/budget7500
```

## Scoring rule (set before the 100-question run)

1. The judge classifies each response as an answer or a refusal.
2. A refusal gets no score. It is **justified** if any gold source was missing from the answerer's context, and **unjustified** otherwise. C0 refusals are labelled only "refusal".
3. An answer gets a 1–10 score and a grounded flag, judged against the wiki, the raw files and the reference answer. The judge also records whether the answer explicitly says it goes beyond the course material.

Each question ends in one of these outcomes: `grounded_answer`, `flagged_ungrounded` (ungrounded, but it told the student), `fabrication` (ungrounded and unflagged), `justified_refusal`, or `unjustified_refusal`.
